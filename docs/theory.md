# Теоретические вопросы

## 1. Системы управления версиями

Система управления версиями хранит историю изменения файлов, позволяет
сравнивать версии, возвращаться к предыдущему состоянию и совместно работать
над проектом. В локальной системе история находится только на одном
компьютере. В централизованной системе имеется единый сервер. В
распределённой системе каждый разработчик получает полную копию репозитория.
Git является распределённой системой контроля версий.

## 2. Создание и клонирование репозитория

`git init` создаёт новый локальный репозиторий в текущей директории.
`git clone <url>` загружает существующий удалённый репозиторий вместе с его
историей. Команда `git remote add origin <url>` связывает локальный
репозиторий с удалённым.

## 3. Запись изменений

Файл может быть неизменённым, модифицированным или индексированным.
`git status` показывает текущее состояние, `git add` помещает изменения в
индекс, а `git commit` сохраняет снимок индексированных изменений в истории.
Для обмена с сервером используются `git pull` и `git push`. Ветки создаются
командой `git branch` или `git switch -c`, а объединяются командой
`git merge`.

## 4. Лицензии

Лицензия определяет условия использования и распространения проекта.
MIT и BSD разрешают свободное использование при сохранении уведомления об
авторских правах. Apache 2.0 дополнительно содержит явные патентные условия.
GPL требует распространять производные работы под совместимой свободной
лицензией. Для проекта выбрана простая разрешительная лицензия MIT.

## 5. CI и CD

Непрерывная интеграция (CI) означает частое объединение изменений и их
автоматическую проверку сборкой, анализаторами и тестами. Непрерывная доставка
или развёртывание (CD) автоматизирует подготовку и выпуск проверенной версии.
Это помогает раньше находить ошибки и делает выпуск повторяемым.

## 6. GitHub Actions

GitHub Actions запускает автоматизированные процессы из файлов workflow в
директории `.github/workflows`. Процесс состоит из событий запуска, заданий и
шагов. В этом проекте push или pull request в `main` запускает установку
Python 3.10, проверку стиля и модульные тесты с измерением покрытия.
